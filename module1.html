Модуль 1

Основы: модели, токены и стоимость

Цель модуля — перестать воспринимать LLM как «магию» и увидеть механику: ответ модели вероятностный, за каждый токен вы платите, у каждой модели свои пределы и цена. В итоговом задании вы соберёте LLM-клиент с контролем стоимости. Он станет фундаментом проекта KnowledgeBot.

Как проходить модуль. Сначала курсы теории, затем задания 1.1–1.5. Задание по теме, которую вы уверенно знаете, можно пропустить: итоговое задание покажет, если в ней есть пробел. Модуль засчитан, когда итоговое задание выполнено по всем критериям.
Стек: Python 3.12+, пакеты openai, tiktoken, python-dotenv. Без платного ключа работает локальная модель через Ollama: OpenAI(base_url="http://localhost:11434/v1", api_key="ollama") и модель, например llama3.1.

Задание 1.1

Параметры генерации и недетерминизм

Курсы: LLMs Output Tuning; GenAI Key Concepts Квиз: Q7 Время: ~30 мин
Что делаем: скрипт, который показывает, как параметры генерации меняют ответ. Зачем: один и тот же запрос может дать разные ответы, и это нормальное поведение модели, а не ошибка. Нужно знать, какими параметрами им управлять.

Условие

  1. Отправьте один и тот же творческий запрос по 5 раз при temperature=0 и при temperature=1.2. Посчитайте, сколько разных ответов получилось.
  2. Получите топ-5 кандидатов первого токена ответа с вероятностями (logprobs). Если ваш провайдер не поддерживает logprobs, пропустите этот пункт.
  3. Задайте маленький max_tokens для длинного ответа и обработайте случай, когда ответ обрезан.

Критерии готовности

  • При temperature=0 из 5 запусков не больше 2 разных ответов, при temperature=1.2 — не меньше 3.
  • Скрипт печатает 5 кандидатов первого токена и их вероятности в процентах.
  • Обрезанный ответ определяется по finish_reason == "length", и скрипт сообщает об этом.
Подсказки
  • Вероятность из logprob: math.exp(logprob).
  • temperature=0 делает ответ почти, но не всегда полностью стабильным. Поэтому в критерии допускается 2 разных ответа.
  • Причина остановки лежит в response.choices[0].finish_reason.
Показать решение

Откройте после собственной попытки.

# params_demo.py
import math
from collections import Counter
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
client = OpenAI()      # Ollama: OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
MODEL = "gpt-4o-mini"  # Ollama: например "llama3.1"

def ask(prompt: str, **params):
    r = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user", "content": prompt}],
        **params,
    )
    return r.choices[0]

# 1. Разброс ответов при разной температуре
prompt = "Придумай одно название для кофейни. Ответь только названием."
for t in (0.0, 1.2):
    answers = [ask(prompt, temperature=t).message.content.strip() for _ in range(5)]
    print(f"temperature={t}: {len(set(answers))} разных из 5 -> {Counter(answers).most_common(3)}")

# 2. Кандидаты первого токена ответа
choice = ask("Продолжи одним словом: небо обычно ...",
             max_tokens=1, logprobs=True, top_logprobs=5)
for cand in choice.logprobs.content[0].top_logprobs:
    print(f"{cand.token!r:15} {math.exp(cand.logprob):6.1%}")

# 3. Обрезка ответа по max_tokens
choice = ask("Перечисли 20 столиц Европы через запятую.", max_tokens=15)
if choice.finish_reason == "length":
    print("Ответ обрезан по max_tokens:", choice.message.content)
Вывод: ответ LLM вероятностный, поэтому его всегда нужно проверять. Для задач, где нужна стабильность (классификация, извлечение полей), ставьте низкую температуру, а max_tokens ограничивает и длину, и стоимость ответа.
Задание 1.2

Токены и контекстное окно

Курсы: Introduction to LLMs; GenAI Key Concepts (Context Management); Token Optimization Квиз: Q10 Время: ~30 мин
Что делаем: счётчик токенов и проверку, что запрос помещается в окно модели. Зачем: вы платите за токены, а контекстное окно ограничивает вход и выход вместе. Это нужно уметь измерять до отправки запроса.

Условие

  1. Напишите count_tokens(text) на tiktoken и сравните результат с usage.prompt_tokens из ответа API для того же текста.
  2. Посчитайте токены одной и той же фразы на русском и на английском и выведите их соотношение.
  3. Напишите fits(input_tokens, max_output_tokens, window). Проверьте случай из квиза: окно 128K, вход 120K, ответ 20K.
  4. Напишите trim_to_budget(text, budget), который обрезает текст до заданного числа токенов.

Критерии готовности

  • count_tokens и usage.prompt_tokens расходятся не больше чем на 10 токенов. Разница — служебные токены разметки сообщений.
  • Выведено соотношение «токены RU / токены EN» для одной фразы.
  • fits(120_000, 20_000, 128_000) возвращает False, fits(100_000, 20_000, 128_000) — True.
  • После trim_to_budget(text, 50) в тексте не больше 50 токенов.
Подсказки
  • Для моделей семейства GPT-4o используйте tiktoken.get_encoding("o200k_base").
  • У моделей Ollama свои токенизаторы, поэтому tiktoken даёт для них только приблизительное число.
  • Окно модели — это сумма входа и выхода, а не только вход.
Показать решение

Откройте после собственной попытки.

# tokens_demo.py
import tiktoken
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
enc = tiktoken.get_encoding("o200k_base")

def count_tokens(text: str) -> int:
    return len(enc.encode(text))

# 1. Сверка с API
client = OpenAI()
text = "Кратко перескажи: модель предсказывает следующий токен. " * 20
r = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": text}],
    max_tokens=50,
)
print("tiktoken:", count_tokens(text), "API:", r.usage.prompt_tokens)

# 2. Русский и английский
ru = "Модель предсказывает следующий токен на основе предыдущих."
en = "The model predicts the next token based on the previous ones."
print("RU:", count_tokens(ru), "EN:", count_tokens(en),
      "соотношение:", round(count_tokens(ru) / count_tokens(en), 2))

# 3. Окно — это вход + выход
def fits(input_tokens: int, max_output_tokens: int, window: int) -> bool:
    return input_tokens + max_output_tokens <= window

assert not fits(120_000, 20_000, 128_000)
assert fits(100_000, 20_000, 128_000)

# 4. Обрезка до бюджета
def trim_to_budget(text: str, budget: int) -> str:
    tokens = enc.encode(text)
    return text if len(tokens) <= budget else enc.decode(tokens[:budget])

assert count_tokens(trim_to_budget(text, 50)) <= 50
Вывод: токен — не слово и не буква, и русский текст обычно дороже английского. Проверяйте, помещается ли запрос в окно вместе с ответом, до отправки, а не по ошибке от API.
Задание 1.3

Стоимость и выбор модели

Курсы: GenAI Key Concepts (LLM Providers; Tokens, Economics & Pricing) Квиз: Q8 Время: ~60 мин
Что делаем: сравниваем модели по цене, скорости и качеству и считаем, сколько экономит выбор модели под задачу. Зачем: выбор модели — главный рычаг стоимости. Простые задачи не нужно отправлять в самую мощную модель.

Условие

  1. Напишите estimate_cost(model, input_tokens, output_tokens) по ценам за 1M токенов. Цены возьмите из актуального прайса провайдера.
  2. Подготовьте 10 запросов: 5 простых (переформулировать, исправить опечатки, оформить список) и 5 сложных (анализ, план, сравнение). Прогоните их на 2 моделях: маленькой и большой.
  3. Для каждого ответа сохраните модель, тип задачи, задержку, стоимость и вашу оценку качества от 1 до 5.
  4. Посчитайте месячную стоимость для 500 запросов в день, где 90% простые: всё на большой модели против выбора модели по типу задачи.
  5. Покажите, что переход между провайдерами (например, OpenAI и Ollama) меняет только base_url и название модели.

Критерии готовности

  • Есть таблица результатов (module1_models.json или Markdown): модель, тип задачи, задержка, стоимость, оценка.
  • Посчитана месячная стоимость двух стратегий и разница между ними.
  • Есть вывод, на какой модели простые задачи не теряют в качестве (разница средних оценок с большой моделью не больше 0,5).
  • Один и тот же код работает с двумя провайдерами.
Подсказки
  • Задержку меряйте через time.perf_counter() до и после вызова.
  • Если платного ключа нет, сравните две локальные модели Ollama разного размера, а цены возьмите из прайса облачного провайдера для похожих моделей.

# models_compare.py
import json, time
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
# Цены за 1M токенов — ПРИМЕР. Подставьте актуальные из прайса провайдера.
MODELS = {
    "small": {"name": "gpt-4o-mini", "in": 0.15, "out": 0.60},
    "large": {"name": "gpt-4o",      "in": 2.50, "out": 10.00},
}

def estimate_cost(key: str, input_tokens: int, output_tokens: int) -> float:
    p = MODELS[key]
    return (input_tokens * p["in"] + output_tokens * p["out"]) / 1_000_000

TASKS = [
    ("simple", "Переформулируй вежливо: «пришлите отчёт до вечера»"),
    ("simple", "Исправь опечатки: «зделать рефакторинг модуля оплты»"),
    # ... ещё 3 простых
    ("complex", "Сравни REST и gRPC для внутреннего API из 30 сервисов, дай рекомендацию"),
    ("complex", "Составь план миграции монолита на микросервисы для команды из 5 человек"),
    # ... ещё 3 сложных
]

client = OpenAI()  # Ollama: OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
rows = []
for key, spec in MODELS.items():
    for kind, prompt in TASKS:
        start = time.perf_counter()
        r = client.chat.completions.create(
            model=spec["name"], messages=[{"role": "user", "content": prompt}])
        rows.append({
            "model": key, "kind": kind,
            "latency_s": round(time.perf_counter() - start, 2),
            "cost_usd": estimate_cost(key, r.usage.prompt_tokens, r.usage.completion_tokens),
            "answer": r.choices[0].message.content,
            "score": None,  # оценку 1–5 ставите вручную после прогона
        })

with open("module1_models.json", "w", encoding="utf-8") as f:
    json.dump(rows, f, ensure_ascii=False, indent=2)

# Месячная стоимость двух стратегий
def choose_model(kind: str) -> str:
    return "small" if kind == "simple" else "large"

def monthly(per_day: int, share_simple: float, routed: bool,
            avg_in: int = 400, avg_out: int = 300, days: int = 22) -> float:
    total = 0.0
    for kind, share in (("simple", share_simple), ("complex", 1 - share_simple)):
        key = choose_model(kind) if routed else "large"
        total += per_day * share * estimate_cost(key, avg_in, avg_out)
    return total * days

all_large = monthly(500, 0.9, routed=False)
routed = monthly(500, 0.9, routed=True)
print(f"всё на large: ${all_large:.2f}/мес, по типу задачи: ${routed:.2f}/мес, "
      f"экономия {1 - routed / all_large:.0%}")
Вывод: выбор модели — инженерное решение по данным: цена, задержка, качество на ваших задачах. Модель «новее и мощнее» — не аргумент.
Задание 1.4

Использование LLM через API

Курсы: AI Applications Development → LLMs API Квиз: вопросов нет — задание обязательно Время: ~60 мин
Что делаем: переиспользуемый класс LLMClient. Зачем: все следующие модули вызывают модель через него. Клиент должен возвращать токены, поддерживать диалог и streaming и правильно обрабатывать ошибки.

Условие

  1. Метод chat(messages, model=None, **params) принимает историю сообщений с ролями system, user, assistant и возвращает объект с текстом, моделью и числом входных и выходных токенов.
  2. Метод ask(prompt, system=None, **params) — короткая форма для одного вопроса.
  3. Метод stream(prompt) отдаёт ответ по частям.
  4. Повторы только для временных ошибок (429, 5xx, таймаут, нет соединения): не больше 3 раз, пауза растёт (1, 2, 4 с). Ошибки 401 и 400 повторять нельзя, повтор их не исправит.

Критерии готовности

  • ask() возвращает текст и число токенов, а не просто строку.
  • Диалог из 3 реплик через chat(): модель помнит, что пользователь сказал в первой реплике.
  • stream() выводит ответ по частям, а не одним блоком.
  • Тест с подменой API без сети: две ошибки 429, потом успех — три вызова и результат. Ошибка 401 — один вызов и исключение.
  • Ошибки не превращаются в строку ответа: вызывающий код получает исключение.
Подсказки
  • Классы ошибок SDK: openai.RateLimitError, openai.APIConnectionError (таймаут — его подкласс), openai.InternalServerError, openai.AuthenticationError, openai.BadRequestError.
  • У SDK есть свои повторы. Отключите их (OpenAI(max_retries=0)), чтобы повторами управлял ваш код.
  • Для теста замените client на unittest.mock.MagicMock, а time.sleep — на функцию, которая ничего не делает.

# llm_client.py
import time
from dataclasses import dataclass
import openai
from openai import OpenAI

# Временные ошибки: повтор может помочь. APITimeoutError — подкласс APIConnectionError.
RETRYABLE = (openai.RateLimitError, openai.APIConnectionError, openai.InternalServerError)

@dataclass
class Answer:
    text: str
    model: str
    input_tokens: int
    output_tokens: int

class LLMClient:
    def __init__(self, model: str = "gpt-4o-mini", base_url: str | None = None,
                 api_key: str | None = None, max_retries: int = 3, timeout: float = 30):
        # max_retries=0: повторами управляет наш код, а не SDK
        self.client = OpenAI(base_url=base_url, api_key=api_key,
                             max_retries=0, timeout=timeout)
        self.model = model
        self.max_retries = max_retries

    def chat(self, messages: list[dict], model: str | None = None, **params) -> Answer:
        for attempt in range(self.max_retries + 1):
            try:
                r = self.client.chat.completions.create(
                    model=model or self.model, messages=messages, **params)
                return Answer(r.choices[0].message.content, r.model,
                              r.usage.prompt_tokens, r.usage.completion_tokens)
            except RETRYABLE:
                if attempt == self.max_retries:
                    raise
                time.sleep(2 ** attempt)  # 1, 2, 4 секунды
        # AuthenticationError, BadRequestError не ловим: повтор не поможет

    def ask(self, prompt: str, system: str | None = None, **params) -> Answer:
        messages = [{"role": "system", "content": system}] if system else []
        messages.append({"role": "user", "content": prompt})
        return self.chat(messages, **params)

    def stream(self, prompt: str):
        stream = self.client.chat.completions.create(
            model=self.model,
            messages=[{"role": "user", "content": prompt}],
            stream=True,
        )
        for chunk in stream:
            if chunk.choices and chunk.choices[0].delta.content:
                yield chunk.choices[0].delta.content

# test_llm_client.py — запуск: pytest -q
from unittest.mock import MagicMock
import httpx, openai, pytest
import llm_client
from llm_client import LLMClient

def api_error(cls, status):
    request = httpx.Request("POST", "https://api.test/v1/chat/completions")
    return cls("error", response=httpx.Response(status, request=request), body=None)

def ok_response():
    r = MagicMock()
    r.choices[0].message.content = "ok"
    r.model = "test-model"
    r.usage.prompt_tokens, r.usage.completion_tokens = 5, 1
    return r

@pytest.fixture
def bot(monkeypatch):
    monkeypatch.setattr(llm_client.time, "sleep", lambda s: None)
    b = LLMClient(api_key="test")
    b.client = MagicMock()
    return b

def test_retries_rate_limit(bot):
    create = bot.client.chat.completions.create
    create.side_effect = [api_error(openai.RateLimitError, 429),
                          api_error(openai.RateLimitError, 429), ok_response()]
    assert bot.ask("привет").text == "ok"
    assert create.call_count == 3

def test_no_retry_on_auth_error(bot):
    create = bot.client.chat.completions.create
    create.side_effect = api_error(openai.AuthenticationError, 401)
    with pytest.raises(openai.AuthenticationError):
        bot.ask("привет")
    assert create.call_count == 1
Вывод: повторять стоит только то, что может пройти со второго раза. Ошибка должна доходить до вызывающего кода, а не прятаться в строке ответа: иначе программа примет текст ошибки за ответ модели.
Задание 1.5

Гигиена контекста в coding agents

Курсы: Token Optimization for AI-Assisted SDLC Квиз: Q1, Q2, Q3 Время: ~45 мин
Что делаем: три приёма экономии контекста в Copilot, Cursor или Claude Code на учебном проекте. Зачем: в работе с агентом токены тратятся быстрее всего на лишний контекст: весь репозиторий, длинную историю, вывод тестов. Чем меньше лишнего, тем дешевле и точнее ответ.

Условие

  1. Точная ссылка на файлы. Дайте агенту одну и ту же задачу дважды: с @workspace / @Codebase и с точной ссылкой @file или @folder. Запишите размер контекста в обоих случаях.
  2. Handoff-файл. В конце рабочей сессии попросите агента записать в handoff.md принятые решения, сделанное, открытые вопросы и следующий шаг. Начните новую сессию с этого файла вместо старой истории.
  3. Вывод тестов в файл. Добавьте в файл правил агента (CLAUDE.md, .cursor/rules или .github/copilot-instructions.md) правило: полный вывод тестов писать в файл, в разговор возвращать только упавшие тесты или последние строки.

Критерии готовности

  • Есть таблица двух замеров: способ ссылки, размер контекста, качество ответа.
  • handoff.md короче 40 строк и содержит 4 раздела. Новая сессия продолжает задачу, не спрашивая заново про принятые решения.
  • Правило лежит в файле правил, и в следующей сессии агент следует ему: в разговоре видны только упавшие тесты.
Подсказки
  • Размер контекста: в Claude Code — команды /context и /cost, в Cursor — индикатор заполнения контекста в чате, в Copilot — список использованных ссылок под ответом.
  • После долгого перерыва кэш промпта обычно уже истёк, и продолжение старой сессии отправляет всю историю по полной цене. Поэтому handoff-файл дешевле.

Итоговое задание модуля

LLM-клиент с контролем стоимости

Подтемы: 1.1–1.4 Время: 2–4 часа Сдача: код + заметка о решениях
Сценарий: команда запускает внутреннего AI-помощника. Бюджет ограничен, запросы бывают простые и сложные, пользователи иногда присылают очень длинные тексты. Нужен клиент, который сам выбирает модель, не выходит за окно контекста и бюджет и записывает, сколько стоил каждый запрос.

Требования

  1. Выбор модели. Метод ask(prompt, task="simple" | "complex", ...) берёт модель из конфигурации по типу задачи. Неизвестный тип задачи — ошибка.
  2. Окно контекста. До вызова API клиент проверяет, что вход и max_tokens помещаются в окно модели. Если передана история, старые сообщения удаляются, системное сообщение остаётся. Если не помещается даже без истории — ContextOverflowError, API не вызывается.
  3. Бюджет. Если оценка стоимости запроса превышает остаток бюджета — BudgetExceededError до вызова API. Потраченное считается по фактическому usage.
  4. Журнал. Каждый успешный запрос — строка в usage.jsonl: время, модель, тип задачи, токены, стоимость, задержка. Текст запроса в журнал не пишется.
  5. Повторы — как в задании 1.4: только временные ошибки.
  6. Стабильный режим. deterministic=True ставит temperature=0.
  7. Провайдеры. Переход между OpenAI и Ollama — только изменение конфигурации.

Критерии приёмки

Подтема Критерий
1.3 Выбор модели task="simple" и task="complex" уходят в разные модели из конфигурации; неизвестный тип — ошибка без вызова API.
1.2 Окно контекста Вход с историей не помещается в окно вместе с max_tokens: старые сообщения удалены, запрос помещается. Если не помещается сам вопрос — ContextOverflowError без вызова API. Системное сообщение сохраняется всегда.
1.3 Стоимость Стоимость в журнале совпадает с расчётом по usage и ценам из конфигурации. BudgetExceededError возникает до вызова API.
1.4 API и ошибки Тест без сети: 429 повторяется не больше 3 раз, 401 не повторяется.
1.1 Параметры deterministic=True передаёт в API temperature=0.
Безопасность журнала В usage.jsonl нет текста запросов.
Провайдеры Один и тот же код работает с OpenAI и Ollama.

Заметка о решениях (до полстраницы)

  • Какие модели выбраны для простых и сложных задач и почему (данные из задания 1.3).
  • Как оценивается стоимость запроса до вызова API и где эта оценка неточна.
  • Сколько стоил прогон 20 тестовых запросов и сколько сэкономил выбор модели.
Проверка: в базовой версии программы ментор проверяет по таблице критериев. Критерии записаны так, что каждый можно превратить в автотест. Эталонное решение есть у ментора.
